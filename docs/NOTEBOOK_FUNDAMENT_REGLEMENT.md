# Регламент: вкладка «Фундамент» (Рабочая тетрадка)

Краткий фон по эмитенту (карточка в стиле NBIS, ~20 секунд чтения).

Связанные файлы: [`TRADING_NOTEBOOK.md`](TRADING_NOTEBOOK.md), UI `/notebook` → вкладка **Фундамент**, API `PATCH /api/notebook/tickers/{sym}/fundament`, `GET …/fundament/suggest`.

---

## 0. Где Настя что правит («тезис» ≠ одно поле)

В UI слово **«тезис»** встречается в двух местах. Это **разные** сущности.

| Что | Где в `/notebook` | Поля | Кнопка сохранения | Связь с Вердиктом |
|-----|-------------------|------|-------------------|-------------------|
| **Фундамент (карточка NBIS)** — суть бизнеса | вкладка **«Фундамент»** | tagline («Суть бизнеса»), 4 метрики, Маржа, Финансирование, Плюсы, Риски, опц. `filing_url` | **OK · сохранить фундамент** | **Не** гейт. Справка для удержания |
| **Макро-тезис плана** — «история ещё жива?» | вкладка **«Тактика входа / выхода»** | **Макро-контекст (тезис словами)** (+ вход/выход) | **OK · сохранить план** | Тумблер **тезис** на **Вердикте** = вкл/выкл этого макро (`macroAlive`). Выкл → СТОП |

**Что править для эталона как у NBIS:** только вкладка **Фундамент** (строка 1 таблицы).

**Что править, если «сломался AI/макро-тезис» и нельзя исполнять Buy Dip:** текст в **Тактике** → поле макро; при сломе — тумблер **тезис** на **Вердикте** выкл. Параллельно на **Фундаменте** усилить **Риски** / поправить Маржу·Финансирование (§5 «Наказание»).

Yahoo «Подтянуть» — основной черновик **цифр**. SEC companyfacts — опциональная сверка (часто непригодна, см. §3). Плюсы/риски/tagline автоматом не пишутся.

## 1. Цель

| Это | Это не |
|-----|--------|
| Справка: суть бизнеса → 4 метрики → маржа/финансирование → плюсы/риски | Гейт Вердикта (Buy/Sell) |
| Фон для «зачем тикер в тетрадке» | Тактика входа/выхода (отдельная вкладка) |
| Ручной текст Насти на вкладке Фундамент + черновик цифр | Автосигнал «покупай / продавай» |
| | Тумблер «тезис» на Вердикте (это макро из Тактики, §0) |

**Анти-цели:** не гейтить BUY/SELL по фундаменту; не автогенерить плюсы/риски из LLM / Seeking Alpha без ручного approve.

## 2. Шаблон полей (эталон NBIS)

Вкладка **Фундамент** (не Тактика):

1. **Tagline** («Суть бизнеса») — 1–2 фразы: что за бизнес (+ опционально категория: «AI Cloud · Neocloud»).
2. **Четыре метрики** (имя / значение / короткий комментарий):
   - Кэш  
   - FCF  
   - Прямой долг  
   - Запас прочности (runway / current ratio / «кэш покрывает CapEx»…)
3. **Маржа** — откуда маржа / контракты / продукт vs сырая мощность.
4. **Финансирование** — кэш, долг, инвесторы, кредитные линии.
5. **Плюсы** — ≥2 пункта (value drivers).
6. **Риски** — ≥2 пункта.
7. **`filing_url`** (опционально) — прямая ссылка на 10-Q / 20-F / IR; иначе кнопка SEC search по тикеру.

## 3. Источники правды

| Слой | Источник | Роль |
|------|----------|------|
| **Основной черновик цифр** | **Yahoo / yfinance** (`Подтянуть из Yahoo`) | Рабочий default для G1+: кэш, FCF (annual CF), долг (BS LT±current), current ratio. Note: «Yahoo …» |
| Опциональная сверка XBRL | **SEC companyfacts** (`Подтянуть из SEC`) | Только если ответ есть **и** note говорит «сравнимо» (тот же FY / тот же BS-период). Иначе **не** править карточку по SEC |
| Правда после earnings | **10-K / 10-Q / IR PDF** (ручной клик по `filing_url` / IR) | Не путать с кнопкой companyfacts: filing — источник сверки, API — черновик |
| Tagline, маржа, финансирование, плюсы, риски | **Только Настя** на вкладке **Фундамент** | Текст карточки NBIS |
| Макро-контекст плана | **Настя / редактор** на вкладке **Тактика** | Текст для тумблера Вердикта |
| Seeking Alpha / дайджест LLM | Новости и контекст | **Не** источник истины по цифрам фундамента |

### 3.1 Практика: SEC companyfacts часто не годится

По аудиту ядра G1 (2026-07-31) и работе в UI:

1. **Таймауты / 404 / нет CIK** — кнопка SEC часто пустая; карточка должна жить на **Yahoo**.
2. **Несопоставимые периоды** — SEC часто отдаёт **10-Q YTD** FCF при Yahoo **annual FY** (пример GOOGL). В note явно: `≠ Yahoo FY`.
3. **Разный состав** — SEC кэш часто *cash only*, Yahoo — *cash+STI*; долг SEC иногда **устаревший** `LongTermDebt` (годы назад → $0 / $1M: ORCL, TER, AMD).
4. **Статическая карта CIK** — промахи ломают тикер целиком (ALAB был с неверным CIK). Нужен fallback `company_tickers.json` или ручная правка карты.
5. **Эталон совпадения Yahoo↔SEC** по G1 — по сути **MSFT**; остальным не ожидать 1:1.

**Правило для Насти:** цифры карточки брать из **Yahoo-черновика** (или вручную из IR/10-K PDF). Кнопку SEC использовать только как подсказку, если note «сравнимо с Yahoo FY / того же периода». При расхождении — верить filing/IR или Yahoo annual, не «последнему» XBRL-факту.

### 3.2 Рекомендации по источникам (roadmap)

| Приоритет | Что | Зачем |
|-----------|-----|--------|
| **P0 (сейчас)** | Опираться на **yfinance** как на основной авточерновик | Стабильнее и полнее по G1, чем companyfacts |
| **P0** | Сверка после earnings — **вручную по 10-K/10-Q/IR**, не по кнопке SEC | Companyfacts ≠ надёжный сверщик |
| **P1** | Либо починить SEC-парсер (FY-prefer, cash+STI, свежий долг, CIK fallback), либо **не рекламировать SEC как сверку** в UI | Иначе ложные «расхождения» |
| **P1** | Оценить **надёжный платный/стабильный API** фин. отчётности (Polygon, Financial Modeling Prep, Intrinio, Bloomberg-lite и т.п.) как замену/дополнение Yahoo+SEC | Если yfinance начнёт деградировать или нужен единый FY-срез |
| **P2** | UX: бейдж «сравнимо / не сравнимо» Yahoo vs SEC | Меньше ручного чтения note |
| **Не делать** | LLM/SA → авто цифры или плюсы/риски без approve | См. §7 |

Полуавтомат: система даёт **Yahoo draft** + ссылку на filings; SEC — best-effort; смысл карточки — ручной.

## 4. Охват и роли

- **Обязательный** полный NBIS-стиль на **Фундаменте** — для **ядра по запросу Насти** (тикеры с позицией / активным планом в G1–G2 в приоритете).
- Остальные тикеры тетрадки — пустая карточка или Yahoo-черновик **без** «сохранить фундамент», пока карточка не утверждена.
- G3 / Watchlist — только по запросу.

| Роль | Делает |
|------|--------|
| Система | **Yahoo draft** (основной); SEC companyfacts best-effort; ссылка filings; overlay |
| Настя | На **Фундаменте**: tagline / метрики (из Yahoo или IR) / плюсы / риски → сохранить. SEC — опционально |
| Алексей / ops | Не подменяет текст; CIK/деплой; оценка альтернативного data vendor (§3.2) |

## 5. Когда обновлять

| Событие | Действие |
|---------|----------|
| Тикер добавлен в ядро / «нужен фундамент» | **Yahoo draft** → Настя правит поля **Фундамента** → **OK · сохранить фундамент** |
| **T+1…T+2 после earnings** | Сверить 4 метрики с **10-K/10-Q/IR PDF** (не полагаться на кнопку SEC); обновить риски при сломе истории |
| Квартальный review | Пройти ядро: устаревшие note «Yahoo, не сверено» — долг |
| SEC кнопка пустая / note «≠ Yahoo FY» | Игнорировать SEC; оставить Yahoo или вписать из IR |

### «Наказание» (отчёт ударил по истории)

Не отдельный авто-гейт. Практика:

1. На **Фундаменте:** усилить **Риски**; при необходимости поправить **Маржа** / **Финансирование** → сохранить фундамент.
2. Если нельзя исполнять план по уровням: на **Тактике** обновить макро-текст; на **Вердикте** выключить тумблер **тезис** (`macroAlive`).

## 6. Definition of Done карточки

Карточка **Фундамента** считается заполненной, если:

- читается за **~20 секунд**;
- есть осмысленный **tagline**;
- **4 метрики** с value и коротким note;
- заполнены **маржа** и **финансирование** (хотя бы по одному абзацу);
- **≥2 плюса** и **≥2 риска**;
- после последнего earnings цифры либо сверены с **filing/IR**, либо в note явно «черновик Yahoo, не сверено».
- совпадение с кнопкой SEC **не** требуется для DoD.

(Макро на Тактике / тумблер Вердикта в DoD фундамента **не** входят.)

---

## 7. Риски полной автоматики (почему не делаем)

- Ложные цифры (TTM vs квартал, GAAP vs non-GAAP; SEC YTD vs Yahoo FY).
- Чужой нарратив (LLM/SA ≠ голос Насти).
- «Красивая» карточка без сверки после отчёта.
- Иностранные эмитенты без 10-Q ломают ожидание «для всех».
- Смешение справки Фундамента с тумблером/гейтом Вердикта.
- Доверие к SEC companyfacts как к «истине» при битых тегах/периодах.

## 8. Фазы продукта

**Фаза 1 (сделано):** регламент; Yahoo draft; UI-подсказка; кнопка/ссылка SEC filings; guide в тетрадке.

**Фаза 2 (сделано, best-effort):** кнопка **Подтянуть из SEC** → `suggest_fundament_from_edgar`; note с периодом FY/YTD; tagline/плюсы/риски не трогает. Практика: **не** считать фазу 2 надёжной сверкой (§3.1).

**Фаза 3 (рекомендуется дальше):**

1. **Контент:** заполнить G1 (и ядро по запросу Насти) по DoD §6 — опора на Yahoo.
2. **Либо** починить SEC (FY-prefer FCF, cash+STI, актуальный долг, CIK из `company_tickers.json`), **либо** понизить SEC в UI до «экспериментально».
3. **Исследовать** стабильный внешний fundamentals API как запасной/основной источник цифр, если Yahoo перестанет хватать (§3.2 P1).
4. UX-бейдж сравнимости периодов (опционально).
